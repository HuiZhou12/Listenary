|---|---|---|---|
| P-17 | 敏感请求头**明文展示 + 明文落盘** | 无 | **可独立修复**（存储层已支持多槽位，见 §4） |

### 1.2 P0/P1 的相互依赖（谁先修才能修谁）
```
P-01(作者面)  ── 前置 ──►  P-21/P-23/P-33/P-45   （同一编辑器内的配套）

P-16(错误表)  ── 前置 ──►  P-07/P-31/P-45/P-50   （探测/试跑想给分类，必须先有唯一分类表）

P-05/P-06/P-07── 依赖 ──►  P-01/P-16              （探测 = 试跑引擎 × N，前提是试跑与判定正确）
```

## 4. 安全迁移设计（D6）——含可验证的兼容性与回滚

### 4.1 现状核对（已完成，代码事实）
- 凭据抽象**按引用（槽位名）读写** ⇒ 天生支持 N 个秘密（`provider/online_music_provider_credentials.dart:12-16`）。
- Windows 实现按 **`targetName` 槽位**存取，注释明确"不同 Provider 可以用不同槽位得到各自的 Key"（`chksz_windows_credential_store.dart:8-9,35,40-41,66-78`）。
- 但**模型只暴露一个** `credentialReference`（`settings.dart:97`），请求头是**裸字符串**（`request_spec.dart:83-97`）。

⇒ **结论：存储层无需重写；需要的是小幅模型调整 + 迁移逻辑。**

### 4.2 最小必要模型调整（提案）
1. `OnlineMusicHeaderSpec` 增加**敏感标记 + 引用形式**：`{name, value?} | {name, credentialReference}`（二者互斥）；敏感头**不得**再用 `value` 承载。
2. 条目从单引用扩展为**命名槽位集合**（例如每个 header/auth 自带 `reference`），并定义**稳定、可迁移**的槽位命名规则（建议 `<providerId>/<headerName>`，避免随机名导致迁移不可预测）。
3. 校验：敏感头若既无引用又无值 ⇒ **保存即报错**（不静默）。

### 4.3 迁移步骤（逐条可验证）
1. 读取旧配置中的 `headers[]`，按启发式识别敏感头（名单 + 高熵判定）**逐项独立**处理。
2. **能安全识别** ⇒ 写入独立槽位 + 把 header 改为引用形式 ⇒ **立即回读校验**（`readCredential` 成功且与原值一致）⇒ 才算迁移成功。
3. **无法可靠识别** ⇒ **保留原配置不动**、标记为"待用户确认"，界面提示**重新配置**（不得删除/覆盖/合并）。
4. **同一 entry 有多个敏感头** ⇒ 每个头一个槽位（存储层已支持）；若实现受限 ⇒ **先报告最小模型调整**再动手（本提案 §4.2 即为此调整）。
5. 迁移**不改变**请求语义：迁移后必须验证"请求头集合与原配置逐项一致"（含非敏感头）。

### 4.4 兼容与回滚策略
| 维度 | 策略 |
|---|---|
| 兼容 | 新旧两种 header 形式并存读取；旧明文配置仍可发请求（只是不满足"无明文"目标） |
| 回滚 | 迁移是**增量**的：写入槽位不删除明文，回滚只需恢复配置字段形式；提供"迁移前配置快照"到 `app_preference.json.bak`（用户可见、可手动恢复） |
| 失败 | 任何一步失败 ⇒ **整条 entry 不迁移**（不半迁移）、记录原因、界面提示重配 |
| 验证 | **迁移测试**（单测：识别/写入/回读/请求头等价）+ **迁移失败测试**（不可识别、写入失败、回读不一致、多敏感头、回滚后仍可用） |
| 不回退 | **不得以"保留明文"为最终方案**（D6 明确）——明文只允许作为迁移中间态存在 |

## 5. 分阶段整改计划

> 每阶段含：目标 / 根因 / 改动范围 / Non-goals / 依赖 / 自动化测试 / 真实服务验证 / 兼容风险 / 完成标准 / 准入下一阶段条件。

### F0 安全边界（最先，无依赖）
- **ID**：P-17、P-18、P-35（+P-36 文案、P-12 静态敏感头部分）
- **目标**：无明文秘密落盘或展示；非法 baseUrl 拒绝保存与发请求；脱敏按值来源
- **根因**：RC-E（脱敏按名、敏感值走明文、静默替换）
- **范围**：`online_music_request_spec`（header 敏感标记/引用）、`preference`（迁移）、设置页显示遮蔽、`normalizeOnlineMusicBaseUrl`、脱敏函数
- **Non-goals**：不做自动登录/Cookie 生命周期/动态签名（D3）；不改凭据存储实现
- **依赖**：无
- **自动化测试**：敏感头不落明文、界面遮蔽、非法 baseUrl 被拒且**不发起请求**、迁移成功/失败两套
- **真实服务验证**：**必须**——故意写错地址，验证不发请求、不发凭据
- **兼容风险**：旧明文配置需保持可用；迁移不得丢/合并（§4）
- **完成标准**：静态扫描无明文路径 + 迁移测试全绿 + 真实验证留证
- **准入条件**：D6 迁移测试通过且回滚演练成功

### F1 作者面修复（RC-A）
- **ID**：P-01、P-02、P-19、P-20、P-21、P-23、P-33、P-38、P-44、P-45、P-61、P-64、P-67（P-46 的 UI 半）
- **目标**：**8/8 能力可保存可试跑**；界面只展示运行时真实可用的能力；破坏性操作有确认与撤销
- **根因**：UI 以手写布尔表达能力差异
- **范围**：`online_music_capability_editor`、`online_music_provider_settings`（builtin 能力声明、填充改合并+确认）、`platform_capability_view`、设置页文案
- **Non-goals**：不新增配置字段、不改模型、不引入"保存即生效"
- **依赖**：F0 的 header 模型改动（同文件）
- **自动化测试**：**非 search 能力的保存/试跑 widget 测试**（补 P-46 盲区）、填充不破坏已有配置、能力集与运行时一致
- **真实服务验证**：可选（用网易云六项配方端到端）
- **兼容风险**：编辑既有配置不得丢字段
- **完成标准**：8 能力"配→试跑→保存→重启→可用"闭环
- **准入条件**：F1 环比 + 兼容测试通过

### F2 判定与状态一致性（RC-C）
- **ID**：P-04、P-14、P-15、P-16、P-22、P-29、P-30、P-31、P-32、P-34、P-36、P-37、P-42(体检)、P-54、P-55、P-56、P-57、P-59、P-63
- **目标**：错误分类**一张表**；草稿/待重启/运行中三态显式；诊断可查；旧旋钮可见可清；**跨 Provider 解析必须可证明同一内容或直接失败**
- **根因**：同一事实多处维护
- **范围**：`online_music_error`（单一映射）、`chksz_error`/声明式/试跑分类收敛、设置页状态区、`routeLog` 上接口 + UI、解析身份校验（强制 `trackId` 映射或失败）
- **Non-goals**：不做保存即生效（D7）；不改重启生效策略
- **依赖**：F1
- **自动化测试**：三层分类一致性（同 401/404 同结论）、三态渲染、跨 Provider 错歌**拒绝**用例
- **真实服务验证**：需要（真实 401/404/限流各一例）
- **兼容风险**：旧旋钮保留读取；错误分类变化会影响既有文案断言
- **完成标准**：同一失败在三层给出一致分类；错歌场景被拒绝而非静默
- **准入条件**：F2 完成后 F3 才可开始（探测要复用统一判定）

### F3 探测重构（RC-D）
- **ID**：P-05、P-06、P-07、P-25、P-26、P-27、P-49、P-50、P-51(文案)
- **目标**：探测 = **试跑引擎 × N 候选 + 四阶段 + confidence**；自建服务可探测；部分成功不得显示为成功
- **根因**：探测定位错误（服务指纹 vs 配置验证）
- **范围**：`declarative/provider_probe`、`provider_templates`（模板退化为"预设 binding"）、`provider_settings_controller.testCapability`（统一引擎）、UI
- **Non-goals**：不做开放式端点扫描；不引入脚本引擎；不做多请求（D2）
- **依赖**：F1 + F2
- **自动化测试**：四阶段各自单测；"部分映射不得判成功"；自定义候选探测；与试跑判定一致性
- **真实服务验证**：需要（网易云 + 一个非模板形状的自建服务）
- **兼容风险**：探测结果模型变化 ⇒ 旧测试重写；UI 文案更新
- **完成标准**：自建 API 可用自己的配置完成探测并得到分阶段结论
- **准入条件**：F3 完成后 F4 的"候选即配置"天然可用

### F4 模型最小表达力（RC-B，按 D1–D5）
- **ID**：P-08（静态常量，D1:A）、P-09（动态头）、P-11（分页生效）、P-12（静态敏感头 + 明确不支持自动登录/签名，D3）、P-13（档位数据化）、P-39（自定义平台，D5:A）、P-40（Content-Type）、P-41（键名放宽；null/转换按 D4 写明范围）、P-65（auth 覆盖冲突报错）
- **目标**：把"必须支持"补齐，并把 D2/D3/D4 的**边界写进模型与界面**
- **根因**：模型只覆盖单次扁平请求
- **范围**：request_spec / response_spec / builder / mapper / capability+platform 模型 / service 契约 / 编辑器 / Spec
- **Non-goals**：**不支持一个能力多请求（D2）**；不做自动登录/签名/令牌刷新（D3）；不引入脚本
- **依赖**：D1–D5 已裁定；F3 之前或并行（但"候选即配置"依赖它）
- **自动化测试**：每种新增能力一个真实形状用例；配置 JSON 往返；不支持项**明确报错**
- **真实服务验证**：需要（至少一个需静态参数 + 一个需自定义平台标识的真实服务）
- **兼容风险**：新增字段必须可缺省；自定义平台标识需持久化并贯穿身份（D5 明确不得推翻现有来源身份模型）
- **完成标准**：自建 API 在**不修改源码**的前提下完成 D1/D3/D5 范围内的接入

### F5 数据层与验证收口（RC-G / RC-F）
- **ID**：P-43（DDL 幂等）、P-60、P-62（级联/刷新语义）、P-28（Dio 释放）、P-46(测试补全)、P-47、P-48、P-58、P-66、P-67、P-68
- **目标**：迁移幂等且可测；资源不泄漏；真实样本与替身层次写清；文档与实现一致
- **Non-goals**：不做与 Provider 无关的库重构
- **依赖**：全程随行；**DB 改动最后做**
- **自动化测试**：迁移测试（含"表已存在"场景）、Dio 释放、聚合异常隔离、仓储层混合平台
- **真实服务验证**：需要（QQ/酷狗至少各一组真实响应样本，或明确记录为未验证）
- **兼容风险**：**最高**（DB），需迁移测试先行 + 可回滚
- **完成标准**：迁移幂等有测试证据；文档与实现无已知矛盾

## 6. 最终 Scope / Non-goals

### Scope（本阶段必须做）
1. **安全**：敏感头不再明文落盘/展示；非法 baseUrl 拒绝；脱敏按值来源；迁移与回滚可验证。
2. **作者面**：8/8 能力可配置可试跑；界面只反映运行时真值；破坏性操作有确认。
3. **判定与状态**：错误分类唯一；三态显式；诊断可查；跨 Provider 解析不得返回无法证明同一内容的曲目。
4. **探测**：平台无关（探测 = 试跑引擎 × N 候选 + 四阶段 + confidence）；自建服务可探测。
5. **模型最小集**：静态常量、动态头、分页生效、静态 Cookie/敏感头经凭据引用、档位数据化、**自定义平台标识**、Content-Type、键名放宽；不支持项明确报错。
6. **验证与数据**：迁移幂等 + 迁移测试；关键路径测试补全；文档与实现对齐。

### Non-goals（本阶段明确不做）
- **一个能力多请求（D2）**——写入模型边界文档；QQ 榜单/复杂艺人页待真实样本后单独设计。
- **自动登录、Cookie 生命周期、动态签名、令牌刷新（D3）**。
- **`null` 与缺失的区分、扩展转换集合（D4）**——接受现状但必须显式报错。
- **"保存即生效"（D7）**——维持重启生效，只补三态显示。
- 不做插件框架/脚本引擎/开放式端点扫描；不做与 Provider 无关的库重构；**不得为单个平台接口加专用分支冒充通用能力**。
